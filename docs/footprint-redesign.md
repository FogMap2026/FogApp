# 발자취 재설계 — 리뷰에서 "길에 남기는 글귀"로

> 상태: **설계 확정 · 구현 전** · 결정자 박근호(PM) · 2026-09-05
> 구현 시 이 문서를 기준으로 삼습니다. 값(반경·횟수)은 팀 합의로 조정 가능하되, **바꾸면 여기부터 고칩니다.**

---

## 1. 무엇이 문제인가

지금 발자취는 **스팟에 남기는 리뷰**입니다. `footprints.spot_id`가 사실상 필수처럼 쓰이고, 작성 진입점도 스팟 상세 화면 하나뿐입니다.

그런데 우리가 원한 건 그게 아닙니다.

> **엘든링의 메시지**처럼, **길목마다** 누군가 남겨둔 짧은 글귀를 지나가다 발견하는 것.

리뷰는 "이 장소가 어땠는가"를 말합니다. 목적지에 도착한 사람이 남기고, 다음 사람은 **갈지 말지 판단하려고** 읽습니다.

글귀는 다릅니다. "여기서 왼쪽 골목이 예쁘다", "이 계단 힘들다", "여기서 하늘 봐라" — **가는 길 위에서** 남기고, **지나가다** 읽습니다. 목적지가 아니라 **경로**에 붙습니다.

이 차이가 앱의 성격을 바꿉니다. 리뷰는 스팟에 도착해야 의미가 생기지만, 글귀는 **이동하는 내내** 읽을 거리가 생깁니다. 안개를 걷으며 걷는 게임에 더 맞는 건 후자입니다.

---

## 2. 바꿀 것 — 한 줄 요약

| | 지금 | 바꾼 뒤 |
|---|---|---|
| **어디에 남기나** | 스팟에 | **지금 내가 선 자리에** (좌표) |
| **어디서 보이나** | 스팟 상세 화면 | **지도 위, 내 주변** |
| **무엇에 붙나** | `spot_id` | **위경도** (스팟은 선택적 연결) |
| **어떻게 보이나** | 목록 카드 | **지도 위 작은 도형** → 탭하면 팝업 |
| **왜 도배가 안 되나** | 막는 장치 없음 | **작성 횟수 제한 + 스팟 정복으로 회복** |

---

## 3. 규칙

### 3-1. 작성 — 내 주변 10m

- 지도 화면에 **발자취 남기기** 버튼을 상시 노출합니다.
- 작성 시 **현재 GPS 좌표**를 함께 보냅니다.
- 서버는 **요청 좌표가 실제 위치에서 10m 이내**인지 검증합니다.

> **왜 10m인가.** "여기"라고 말할 수 있는 범위입니다. 이보다 넓으면 보지도 않은 골목에 글을 남길 수 있고, 좁으면 GPS 오차(도심 5~10m)로 정상 작성이 실패합니다.

> ⚠️ **10m는 "내가 지금 있는 곳"의 허용 오차이지 남이 볼 거리가 아닙니다.** 인증(#48)이 스팟 좌표 기준 100m를 보는 것과 다른 종류의 값입니다.

### 3-2. 조회 — 내 주변 50m

- 이동 중에는 **내 위치 반경 50m** 안의 발자취가 지도에 뜹니다.
- 걸으면 새 발자취가 들어오고 지나온 것은 빠집니다.

> **왜 50m인가.** 걸어서 30초 안에 닿는 거리입니다. 더 넓히면 화면이 글귀로 덮여 "발견"이 아니라 "목록"이 되고, 좁히면 아무것도 안 보이는 구간이 길어집니다.

### 3-3. 스팟 안에서는 150m

- **해금된 스팟의 안개 구멍 안에 들어가면**, 그 스팟 기준 **150m 이내** 발자취가 전부 보입니다.
- 50m 창은 그동안 150m로 넓어집니다.

> **왜 150m인가.** 임의의 숫자가 아니라 **이미 걷힌 안개 반경과 같은 값**입니다(`fog_overlay_controller.dart`의 `radiusMeters = 150`).
>
> **보이는 땅 = 읽히는 글.** 안개가 걷힌 만큼 글귀도 보입니다. 이 규칙이 어긋나면 "안개 속인데 글이 보이거나", "걷혔는데 안 보이는" 이상한 상태가 생깁니다.

> ⚠️ **150m는 인증 반경이 아닙니다.** 인증은 **100m**(`VisitProperties.radiusMeters`)입니다.
> 이 문서에서 셋을 명확히 구분합니다 — **작성 10m · 이동 중 조회 50m · 스팟 안 조회 150m · 인증 100m.**

### 3-4. 스팟을 탭하면 — 지금처럼

- 스팟 상세 시트에서는 **그 스팟에 연결된 발자취를 목록 카드로** 봅니다.
- 지금 화면([#71](../../issues/71)·[#72](../../issues/72))을 그대로 씁니다.

> 지도 위 도형은 **발견**을 위한 것이고, 목록은 **훑어보기**를 위한 것입니다. 둘 다 필요합니다.

### 3-5. 도배 방지 — 횟수 제한과 회복

- 사용자는 **남은 발자취 횟수**를 가집니다. 하나 남기면 1 줄어듭니다.
- **0이면 더 남길 수 없습니다.**
- **스팟을 하나 정복(방문 인증)하면 횟수가 초기화됩니다.**

> **이게 이 설계의 핵심입니다.** 글을 남기는 권리를 **탐험으로 벌게** 만듭니다.
>
> 무제한이면 한 자리에서 수십 개를 쏟아부어 길목이 도배됩니다. 단순히 상한만 두면 다 쓴 뒤 아무것도 못 하게 되고요. **정복으로 회복**시키면 "글을 더 남기고 싶으면 더 걸어라"가 되어, 도배 방지와 탐험 유도가 같은 장치로 해결됩니다.

**초기값 제안 (조정 가능)**

| 항목 | 값 | 근거 |
|---|---|---|
| 가입 시 지급 | 3 | 첫 스팟 정복 전에도 몇 개는 남겨볼 수 있어야 함 |
| 정복 시 회복 | **3으로 리셋** (누적 아님) | 누적이면 아껴뒀다 한 곳에 몰아쓸 수 있음 |

> 리셋인 이유: 누적(`+3`)이면 정복만 반복해 잔량을 쌓아두었다가 한 지점에 몰아쓸 수 있어, 막으려던 도배가 그대로 돌아옵니다.

## 4. 지도 표현

### 4-1. 작은 도형, 확대하면 보임

- 발자취는 **작은 도형**(마름모·점 등)으로 표시합니다. 스팟 마커와 **형태가 확실히 달라야** 합니다.
- **줌 레벨이 낮으면(멀리 보면) 숨깁니다.** 확대해야 나타납니다.

> **왜 숨기나.** 발자취는 스팟보다 훨씬 많아집니다. 다 그리면 지도가 점으로 덮여 **스팟 마커가 묻힙니다.** 탐험의 주역은 스팟이고 발자취는 길 위의 발견이라, 줌으로 계층을 나눕니다.
>
> 임계 줌은 구현하면서 실제 밀도를 보고 정합니다. **"확대하면 보인다"가 규칙이고 숫자는 튜닝값입니다.**

### 4-2. 탭하면 팝업

- 도형을 탭하면 **글귀 전문**이 팝업으로 뜹니다.
- 작성자 닉네임·프로필·작성 시각·좋아요를 함께 보여줍니다 — 목록 응답에 이미 실려 옵니다([#84](../../pull/84)·[#85](../../issues/85)).

> 팝업이지 화면 전환이 아닙니다. **지도를 벗어나지 않아야** 걸으면서 읽는 흐름이 끊기지 않습니다.

## 5. 서버가 바뀌어야 하는 것

### 5-1. 스키마 — 좌표 추가

`footprints`에 **위경도와 `geom`이 없습니다.** 이게 가장 큰 변경입니다.

```sql
ALTER TABLE footprints
    ADD COLUMN lat  DOUBLE PRECISION,
    ADD COLUMN lng  DOUBLE PRECISION,
    ADD COLUMN geom geometry(Point, 4326);

CREATE INDEX idx_footprints_geom ON footprints USING GIST (geom);
```

`geom`은 **DB 트리거가 채웁니다.** `spots`(V2)·`visits`(V4)와 같은 방식입니다 — 작성 경로가 늘어나도 좌표 생성 로직이 한 곳에만 있어야 누락이 생기지 않습니다.

> **기존 행 처리.** 이미 있는 발자취는 좌표가 없습니다. **연결된 스팟 좌표로 채우는 것을 권합니다** — 지도에서 사라지는 것보다 대략 맞는 자리에 있는 게 낫습니다. 좌표를 못 구하면 `geom`은 NULL로 두고 **반경 조회에서 자연히 빠집니다.**

`spot_id`는 **그대로 nullable로 둡니다.** 이미 `ON DELETE SET NULL`이라 스키마 변경이 필요 없고, 길목 발자취는 이 값이 비어 있습니다.

### 5-2. 작성 API

```
POST /api/footprints
{ "content": "...", "photoUrl": null, "lat": 37.5, "lng": 127.0, "spotId": null }
```

서버가 검증할 것:

1. **좌표 범위** — 범위를 벗어나면 PostGIS 캐스팅에서 500이 되므로 먼저 400으로 거릅니다(`VisitService.verify`와 같은 이유)
2. **남은 횟수 > 0** — 아니면 **429**
3. `spotId`가 있으면 **실재하는 스팟인지**

> ⚠️ **10m 검증을 서버가 할 수 없습니다.** 서버는 사용자의 "진짜 위치"를 모릅니다 — 요청에 담긴 좌표가 전부입니다. 인증(#48)은 **스팟이라는 고정 기준점**이 있어 서버가 재검증할 수 있지만, 발자취는 기준점이 없습니다.
>
> **그래서 10m는 앱이 강제하는 UX 규칙입니다.** 서버는 좌표 범위와 횟수만 봅니다. 좌표 위조로 먼 곳에 글을 남기는 것은 **막지 못합니다** — 다만 횟수 제한이 있어 피해가 제한적이고, 신고 기능이 생기면 그때 다룰 문제입니다. **이 한계를 알고 넘어가는 것이지, 놓친 게 아닙니다.**

### 5-3. 조회 API — 반경

```
GET /api/footprints/nearby?lat=&lng=&radius=50
```

`spots`의 반경 조회와 **같은 방식**입니다 — `geom::geography` + `ST_DWithin`, GiST 인덱스가 bbox 사전 필터.

> **상한이 필요합니다.** `SpotQueryService.MAX_RADIUS_METERS`(20km)처럼, 발자취도 최대 반경과 최대 건수를 강제해야 합니다. 안 그러면 `radius=999999`로 전국 발자취를 한 번에 긁어갈 수 있습니다.

기존 `GET /api/footprints?spotId=`는 **그대로 둡니다.** 스팟 상세 목록이 계속 씁니다.

### 5-4. 횟수 관리

`users`에 잔여 횟수를 둡니다.

```sql
ALTER TABLE users ADD COLUMN footprint_quota INT NOT NULL DEFAULT 3;
```

- 발자취 작성 시 **감소**
- **방문 인증 성공 시 3으로 리셋** — `VisitService.verify`가 성공한 직후

> 인증과 리셋은 **같은 트랜잭션**이어야 합니다. 갈라지면 "인증은 됐는데 횟수는 그대로"가 생기고, 사용자는 이유를 알 수 없습니다.

**응답에 잔여 횟수를 실어야 합니다.** 앱이 버튼을 비활성화하려면 알아야 합니다 — `GET /api/profile`에 추가하고, 작성 응답에도 갱신된 값을 함께 돌려주는 편이 왕복이 줄어듭니다.

## 6. 앱이 바뀌어야 하는 것

| 화면 | 변경 |
|---|---|
| 지도 | **발자취 남기기 버튼** 상시 노출 (잔여 0이면 비활성 + 이유 표시) |
| 지도 | 내 위치 반경 **50m** 발자취 조회 — 이동 시 갱신 |
| 지도 | 해금 스팟 안에 들어가면 **150m로 확대** |
| 지도 | 발자취를 **작은 도형**으로 렌더, 줌 임계 이하에서는 숨김 |
| 지도 | 도형 탭 → **글귀 팝업** |
| 작성 | 현재 GPS 좌표 첨부, **10m 이탈 시 작성 차단**(안내 문구) |
| 스팟 상세 | **변경 없음** — 지금 목록 카드 유지 |

> ⚠️ **버튼 겹침을 조심하세요.** 지도 화면에는 이미 줌 컨트롤·내 위치·성향 테스트·동행 추천 버튼이 있고, [#64](../../issues/64)에서 실제로 겹쳐 탭이 먹히지 않는 문제가 있었습니다. 발자취 버튼을 넣을 때 `_MapControls` 레이아웃을 함께 검토할 것.

> ⚠️ **조회 요청 빈도.** 위치가 바뀔 때마다 부르면 걷는 내내 요청이 쏟아집니다. **일정 거리 이상 이동했을 때만** 다시 부르는 식으로 묶어야 합니다(근접 감지 #45가 쓰는 방식 참고).

## 7. 열어둔 결정

구현 전에 팀이 정해야 합니다.

1. **초기 횟수·리셋값** — 3/3은 제안일 뿐입니다. 실제로 걸어보고 "너무 자주 막힌다"면 올립니다.
2. **줌 임계값** — 실제 밀도를 보고 정합니다.
3. **한 자리 중복 방지** — 같은 지점(예: 5m 이내)에 여러 개가 겹칠 때 어떻게 그릴지. 묶어서 "N개" 배지로 보여주는 방법이 있습니다.
4. **기존 발자취 마이그레이션** — 스팟 좌표로 채울지, NULL로 둘지.
5. **신고·삭제** — 공개 글이 지도에 뜨는 순간 필요해집니다. 이번 범위 밖이지만 **출품 전에는 판단해야 합니다.**

## 8. 값 요약 — 헷갈리지 말 것

| 값 | 숫자 | 어디에 |
|---|---|---|
| 발자취 **작성** 허용 오차 | **10m** | 앱이 강제 (서버 검증 불가) |
| 발자취 **조회**(이동 중) | **50m** | `GET /api/footprints/nearby` |
| 발자취 **조회**(스팟 안) | **150m** | 안개 걷힘 반경과 동일 |
| 방문 **인증** 반경 | **100m** | `VisitProperties.radiusMeters` (서버 재검증) |
| 안개 **걷힘** 반경 | **150m** | `fog_overlay_controller.dart` |

> 인증 100m와 안개 150m가 다른 것은 **의도된 차이**입니다 — 인증은 "충분히 가까웠는가"를 엄격히 보고, 안개는 걷힌 느낌을 주려고 조금 넓게 걷습니다.
