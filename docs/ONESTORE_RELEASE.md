## 0. 왜 출시가 "선택"이 아니라 "제출 요건"인가

대회 1차 심사자료 안내가 서비스 유형별 제출물을 이렇게 규정합니다.

> **앱**: 구글 스토어, 애플 스토어, **원스토어** 등 **최소 1개 스토어에 등록 완료된 링크 입력**

**디버그 APK 를 링크로 나눠주는 것으로는 요건을 못 채웁니다.** 실제로 스토어에 올라가 있어야 합니다.

## 왜 원스토어인가

**"최소 1개"** 조건이라 원스토어 하나로 충족됩니다. 그리고 우리 상황에서 원스토어가 압도적으로 빠릅니다.

| | 원스토어 | (참고) Google Play |
|---|---|---|
| 등록비 | **무료** | $25 |
| **신규 개인 계정 테스트 의무** | **없음** | 테스터 12명 × **14일 연속** |
| 심사 시간 | **1~2시간** | 수일 |
| 현실적 총 소요 | **하루** | **3~5주** |

Google Play 는 2023-11-13 이후 만든 개인 개발자 계정에 **"테스터 12명이 14일 연속 참여"** 를 요구합니다. 팀이 5명이라 외부에서 7명을 더 모아야 하고, 그들이 2주를 버텨야 하며, 그 뒤 프로덕션 액세스 심사가 또 붙습니다. **대회 일정에 맞추기 어렵다고 판단해 원스토어 단독으로 갑니다**(2026-09-08 결정).

> 📌 iOS(App Store)도 범위 밖입니다. Apple Developer Program 은 **$99/년**이 매년 나가고,
> 어차피 "최소 1개" 조건이 원스토어로 충족됩니다.

### 우리는 위치기반서비스사업입니다

앱이 단말 GPS 를 직접 수집해 **자기 서비스에 쓰는** 경우는 **위치기반서비스사업 신고** 대상입니다. 위치정보를 **다른 사업자에게 제공**하는 위치정보사업(허가)은 해당하지 않습니다 — 더 무거운 쪽이 아닙니다.

### 어떤 신고를 냈나 — 실제 접수본 기준

**세 갈래를 검토한 끝에 ②로 접수했습니다(2026-09-09 서명 · 09-10 제출).** 아래는 실제 접수본 기준입니다.

| | 실제 |
|---|---|
| 신고 종류 | **소상공인등의 위치기반서비스사업 신고** — 위치정보법 §9의2, 별지 **제6호의2**서식 |
| 사업의 종류 | 응용 소프트웨어 개발 및 공급업 |
| 제출 서류 | ① 소상공인임을 증명하는 서류 ② **사업의 종류 및 내용에 대한 설명자료** — **2종뿐** |
| 처리기간 | **즉시** *(서식에 그렇게 박혀 있습니다)* |
| 교부물 | **신고확인증** |
| 수수료 | 무료. 지방세법에 따라 **등록면허세가 사후 부과** |

> ⚠️ **「신고필증」·「처리기간 5~6일」은 일반 신고(§9, 별지 제6호서식) 기준입니다.** 우리가 낸 특례
> 신고는 서식도 교부물도 처리기간도 다릅니다. 예전 문서에 그렇게 적혀 있던 것을 정정합니다.

**소상공인 갈래를 고른 이유** — 특례에는 소상공인과 1인창조기업 두 갈래가 있는데, **1인창조기업은
상시근로자 0명**을 요구하고 **소상공인(정보통신업)은 5명 미만**이면 됩니다. 팀이 5명이라 자격 판단에
여지를 남기지 않는 쪽을 골랐습니다.

> 📌 **1개월은 대기가 아니라 유예입니다.** 조문은 *"신고하지 아니하고 사업을 할 수 있다. 다만
> 개시 1개월이 지난 후에도 계속하려면 신고하여야 한다"* 라, **의무 발생 시점을 늦춘 것**이지
> 신고 가능 시점을 미룬 것이 아닙니다. 원스토어가 신고 결과를 요구하므로 기다릴 이유가 없었습니다.

### 🔴 접수본에 **아직 없는 기능**이 적혀 있습니다

설명자료 「방식」 항목이 이렇게 적고 있습니다.

> 이용자가 **위치공유 기능**을 이용하는 경우 현재 위치정보를 서버로 전송하되, 해당 위치를 다른
> 이용자에게 즉시 제공하지 않고 **측정 시점으로부터 30분이 경과한 위치정보만 지연하여 제공**함.
> 공개되는 위치정보는 **이용자별 최신 위치 1건만 유지**하며, 이전 공개 위치정보는 갱신 시 삭제
> 또는 덮어쓰기하는 방식으로 운영함.

**이것은 [#133](../../issues/133)(주변 여행자 익명 표시 — 30분 텀)이고, 앱에 구현돼 있지 않습니다.**
그리고 [게시된 개인정보처리방침](store/privacy-policy.html) §5 는 다른 이용자에게 공개되는 것을
**발자취 내용·지점·닉네임·프로필, 동행 추천 시 닉네임·성향**으로만 열거합니다 — **「현재 위치」가 없습니다.**

```
접수한 신고   위치공유(30분 지연) 있음
앱            없음  (#133 미구현)
게시 방침     없음
```

### ✅ 결정 — [#133](../../issues/133)을 **마감 전에 구현**합니다 (09-11)

변경신고로 문단을 빼는 방법도 있었지만, **접수 내용대로 만드는 쪽**으로 정했습니다.

**그래서 접수본이 곧 명세입니다.** 문장에서 뽑아낸 구속 조건 넷 — 여기서 벗어나면 변경신고 대상입니다.

| # | 접수본 문구 | 구현 제약 |
|---|---|---|
| 1 | *"이용자가 위치공유 기능을 **이용하는 경우**"* | **opt-in.** 켜지 않은 사람의 위치는 게시되지 않습니다 |
| 2 | *"**30분이 경과한** 위치정보만 지연하여 제공"* | 실시간 금지 — 조회 시점에 30분 이상 지난 것만 |
| 3 | *"이용자별 **최신 위치 1건만 유지**"* | **이력 테이블 금지.** 사용자당 한 행 |
| 4 | *"갱신 시 **삭제 또는 덮어쓰기**"* | `INSERT` 가 아니라 **`UPSERT`** |

> 🔴 **3·4번을 놓치기 쉽습니다.** 「30분 전 값을 조회」하려고 위치 이력 테이블을 만들면
> **이동 경로가 서버에 쌓여 접수본과 어긋납니다.** 한 행을 덮어쓰되 기록 시각을 함께 두고,
> 30분이 안 지났으면 응답에서 빼는 쪽이 조건을 만족합니다.

**[#133](../../issues/133)의 원래 설계(익명 · 스팟 기준)는 접수본보다 좁습니다** — 좌표 대신 가장 가까운
스팟 id 로 환산합니다. **신고보다 좁게 구현하는 것은 문제없습니다.**

## 2. 릴리스 서명 — 설정 완료

예전에는 `release` 가 `signingConfigs.getByName("debug")` 를 써서 **디버그 키로 서명**됐고, 그건
어느 스토어에도 못 올립니다. 지금은 릴리스 키로 서명합니다.

서명 키는 **두 경로**로 읽습니다.

| | 어디서 |
|---|---|
| 로컬 | `app/android/key.properties` — **gitignored** |
| CI | `KEYSTORE_PATH` · `KEYSTORE_PASSWORD` · `KEY_ALIAS` · `KEY_PASSWORD` |

키스토어는 **PKCS12** 입니다(JKS 는 `keytool` 이 "outdated, 향후 제거" 경고를 냅니다).
`storeType = "PKCS12"` 를 명시해 뒀습니다 — AGP 가 자동 인식하기도 하지만 버전마다 달라질 수 있고,
틀리면 원인 메시지가 불친절합니다.

> ⛔ **키스토어와 비밀번호는 저장소에 커밋하지 않습니다.** `.gitignore` 가 `key.properties`·
> `*.jks`·`*.keystore` 를 막습니다.

> 🔴 **키를 잃어버리면 앱을 영영 업데이트할 수 없습니다.** 키스토어와 비밀번호를 **담당자 PC
> 한 곳에만 두지 마세요.** 다른 저장소에 한 벌 더 보관하고, 비밀번호는 **비공개 채널로** 팀에
> 공유하세요 — 이슈·PR 에 붙이면 안 됩니다.

### `Release APK` 잡이 막는 것 네 가지

**제출물이 조용히 망가지는 경로를 전부 CI 에서 끊습니다.**

| 검사 | 없으면 생기는 일 |
|---|---|
| 서명 시크릿 없으면 **잡 스킵** | 디버그 키로 서명된 `app-release.apk` 가 생겨 **파일 이름만 보고 올리게 됨** |
| **`API_BASE_URL` 비어 있으면 실패** | `--dart-define=API_BASE_URL=` 는 *키는 정의되고 값만 빈 문자열*. `String.fromEnvironment` 의 기본값이 안 먹어 `baseUrl: ""` 이 되고 **모든 요청이 실패** |
| **서명 주체 검사**(`apksigner`) | 설정이 어긋나 디버그 키로 서명돼도 모름 |
| **APK 안의 주소 대조** | 시크릿을 고쳤는데 엉뚱한 주소로 구워진 APK 가 나감 |

> ⚠️ 서명 검사에 `keytool -printcert -jarfile` 을 쓰지 마세요. **v1(JAR) 서명만 읽습니다.**
> 우리 APK 는 v2 로만 서명돼 있어 "서명이 없다" 로 보입니다. `apksigner` 를 씁니다.

**이 잡은 수동 실행과 `dev`·`main` push 에서만 돕니다.** 제출물은 주소가 확정된 뒤 한 번 구우면
되는데, 모든 앱 PR 에서 돌리면 리뷰 회전이 느려집니다.

### 바이너리 형식

원스토어는 **APK·AAB 둘 다** 받습니다. CI 가 이미 APK 를 만들고 있어 **APK 로 갑니다.**

| | 현재 |
|---|---|
| `versionCode` | `1` (`version: 0.1.0+1`) — 업로드마다 올려야 합니다 |
| `applicationId` | `com.fogapp.fogapp` — **한 번 정하면 못 바꿉니다** |

## 5-2. 📌 퍼미션 — 원스토어에는 Google Play 식 "민감 권한 심사"가 없습니다

계획 단계에서 **백그라운드 위치(`ACCESS_BACKGROUND_LOCATION`)는 스토어 심사에 수 주가 걸린다** 고 적어뒀는데, 그건 **Google Play 기준**이었습니다. 원스토어로 바뀌었으므로 정정합니다.

| | Google Play | 원스토어 |
|---|---|---|
| 민감 권한 **선언 양식** | 필수 | **없음** |
| 시연 영상 제출 | 필수 | **없음** |
| 권한 심사 기간 | 수 주 | **해당 없음** (전체 심사 1~2시간) |

원스토어 개발자센터는 APK 의 퍼미션 목록을 **표시**하지만, **별도의 퍼미션 제한 가이드는 두고 있지 않습니다.**

> ⚠️ **다만 위치 권한은 위 1-2 의 위치정보 신고 문제와 별개가 아닙니다.** 권한 심사가 없다는 것이
> "위치를 마음대로 써도 된다"는 뜻은 아닙니다. 규제는 스토어가 아니라 **위치정보법** 쪽에 있습니다.

**Phase 6 에 주는 영향**

- [#135](../../issues/135) 백그라운드 위치 — **스토어 심사 때문에 막히지는 않습니다.** 남는 것은 순수한 구현 리스크입니다
- [#133](../../issues/133) 주변 여행자 표시 — **익명 · 30분 텀 · 스팟 기준**입니다. 제3자에게 나가는 응답에 **닉네임·프로필·`userId` 가 전혀 없어**, 실명 정밀 좌표를 제공하는 경우보다 훨씬 가볍습니다.
  다만 **서버는 사용자와 위치를 연결해 저장**하므로("내 것 제외"·주기 판정에 필요) **수집·저장 요건은 1-2 와 같은 건**입니다. 착수 전 확인할 것

<details>
<summary>왜 스프링에 <code>permitAll</code> 을 뚫지 않았나</summary>

파일만 서버에 올려두면 **404 가 아니라 401** 이 났습니다.

```
$ curl -s https://fogapp.taild500a1.ts.net/privacy-policy.html
{"message":"인증이 필요합니다."}
```

응답 본문이 우리 `RestAuthenticationEntryPoint` 였습니다 — 파일이 없어서가 아니라 스프링이 막은 것입니다.

```java
// SecurityConfig.java
.requestMatchers("/api/health").permitAll()
.anyRequest().authenticated()          // ← /api 밖도 여기에 걸린다
```

`SecurityConfig` 에 그 경로만 `permitAll` 로 여는 방법도 있었지만, **방침 한 장 때문에 인증 정책에 예외를 내면 나중에 그 예외가 무엇이었는지 아무도 기억하지 못합니다.** Funnel 경로 서빙은 스프링 설정을 건드리지 않습니다.

</details>

> ⚠️ 앱 화면과 게시본의 문구는 **항상 같아야 합니다.** 한쪽만 고치면 "앱에서 본 방침"과
> "스토어에 걸린 방침"이 달라집니다 — 그 자체가 반려 사유입니다. 지금 세 곳을 함께
