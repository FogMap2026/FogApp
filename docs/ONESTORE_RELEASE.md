## 0. 왜 출시가 "선택"이 아니라 "제출 요건"인가

대회 1차 심사자료 안내가 서비스 유형별 제출물을 이렇게 규정합니다.

> **앱**: 구글 스토어, 애플 스토어, **원스토어** 등 **최소 1개 스토어에 등록 완료된 링크 입력**

**디버그 APK 를 링크로 나눠주는 것으로는 요건을 못 채웁니다.** 실제로 스토어에 올라가 있어야 합니다.

## 왜 원스토어인가

**"최소 1개"** 조건이라 원스토어 하나로 충족됩니다. 그리고 우리 상황에서 원스토어가 압도적으로 빠릅니다.

| | 원스토어 | (참고) Google Play |
|---|---|---|
| 등록비 | **무료** | $25 |
| **신규 개인 계정 테스트 의무** | **없음** | 테스터 12명 × **14일 연속** |
| 심사 시간 | **1~2시간** | 수일 |
| 현실적 총 소요 | **하루** | **3~5주** |

Google Play 는 2023-11-13 이후 만든 개인 개발자 계정에 **"테스터 12명이 14일 연속 참여"** 를 요구합니다. 팀이 5명이라 외부에서 7명을 더 모아야 하고, 그들이 2주를 버텨야 하며, 그 뒤 프로덕션 액세스 심사가 또 붙습니다. **대회 일정에 맞추기 어렵다고 판단해 원스토어 단독으로 갑니다**(2026-09-08 결정).

> 📌 iOS(App Store)도 범위 밖입니다. Apple Developer Program 은 **$99/년**이 매년 나가고,
> 어차피 "최소 1개" 조건이 원스토어로 충족됩니다.

## 2. 코드에서 막혀 있는 것 — 릴리스 서명

[`app/android/app/build.gradle.kts`](../app/android/app/build.gradle.kts) 현재 상태:

```kotlin
buildTypes {
    release {
        // TODO: Add your own signing config for the release build.
        signingConfig = signingConfigs.getByName("debug")   // ← 이대로는 스토어에 못 올립니다
    }
}
```

**디버그 키로 서명된 빌드는 스토어용이 아닙니다.** 릴리스 키스토어를 만들어 서명해야 합니다.

> ⛔ **키스토어(`.jks`)와 비밀번호는 저장소에 커밋하지 않습니다.** `.env`·서비스 계정 키와 같은
> 취급입니다. CI 에서는 base64 로 인코딩해 **저장소 시크릿**에 넣고 빌드 시 복원합니다.
>
> ⚠️ **키를 잃어버리면 앱을 업데이트할 수 없습니다.** 원스토어도 앱 서명 기능을 제공하므로,
> 등록 시 서명 옵션을 확인하고 키를 안전한 곳에 별도 보관하세요.

**바이너리 형식은 APK·AAB 둘 다 됩니다.** 지금 CI 가 이미 APK 를 만들고 있으므로, **릴리스 서명만 붙이면 APK 로 바로 갑니다** — 형식을 바꿀 이유가 없습니다.

| | 현재 | 할 일 |
|---|---|---|
| 서명 | 디버그 키 | 릴리스 키스토어 + `key.properties` |
| 빌드 | `flutter build apk --debug` | `flutter build apk --release` 잡 추가 |
| `versionCode` | `1` (`version: 0.1.0+1`) | 업로드마다 올려야 합니다 |
| `applicationId` | `com.fogapp.fogapp` | **한 번 정하면 못 바꿉니다.** 확정 필요 |

## 3. 스토어 등록에 필요한 자료 (코드 밖의 일)

| | 규격·비고 |
|---|---|
| 상품 제목 | |
| 한줄 설명 | |
| 상품 설명 | |
| 대표 아이콘 | **512 × 512** |
| 그래픽 이미지 | **1024 × 578** |
| 스크린샷 | **2 ~ 8장** |
| **개인정보처리방침 URL** | 위치·카메라 권한을 쓰므로 필요합니다. **공개 URL** 이어야 합니다 |
| 가격 | **무료**에 체크 |

> 정확한 규격은 등록 화면에서 최종 확인하세요. 위 값은 사전 조사 기준입니다.

> 💡 **개인정보처리방침 URL 은 인프라가 붙일 수 있습니다.** 이미 공개 HTTPS 서버가 있으니
> 정적 페이지 하나를 서빙하면 됩니다. **문구는 PM 이 써야 합니다** — 실제 수집 항목(위치·사진·
> 이메일)과 어긋나면 정책 위반입니다.

## 4. 🔑 대회 제출용 테스트 계정

심사자료 안내가 **계정 형식을 지정**했습니다. 임의로 만들면 안 됩니다.

| 형식 | ID | PW |
|---|---|---|
| 일반계정 | `openapi` | `2026openapi!` |
| **이메일 계정** | `openapi@메일도메인` | `2026openapi!` |

**우리 앱은 이메일 로그인이므로 이메일 형식을 씁니다.** Firebase Auth 에 이 계정을 만들어 제출합니다.

> ⚠️ 이 계정으로 심사위원이 **실제로 앱을 돌려봅니다.** 만들어만 두면 안 되고, 로그인 → 지도 →
> 스팟 인증까지 되는지 미리 확인해야 합니다.
>
> ⚠️ 발자취 작성 횟수(`users.footprint_quota`)가 기본 3 이라, 심사 중 소진되면 기능을 못 봅니다.
> 제출 전에 이 계정의 잔여 횟수를 확인하세요.

## 5. 🔴 서버가 24시간 떠 있어야 합니다

**스토어 출시에서 가장 큰 영향입니다.**

지금 서버는 **인프라 담당자의 PC** 에서 Tailscale Funnel 로 나갑니다. 우리가 옆에서 시연하는 형식이면 괜찮았지만, **스토어에 올라간 앱을 심사위원이 각자 시간에 설치해 써 본다면** PC 가 꺼져 있는 순간 로그인부터 실패합니다.

**상시 가동 서버로 옮겨야 합니다.** 조사해 둔 선택지 중 **Oracle Cloud Always Free(0원)** 가 우리 스택에 맞습니다 — PostGIS 를 직접 호스팅하고, 200GB 블록 스토리지에 인증 사진 볼륨을 붙일 수 있습니다.

> ⚠️ **서버 주소가 바뀌면 앱을 다시 빌드해 스토어에 올려야 합니다.** `API_BASE_URL` 이 빌드
> 타임에 구워지기 때문입니다. **스토어에 올리기 전에 최종 주소를 확정하세요.** 순서를 반대로
> 하면 심사를 한 번 더 태워야 합니다.

## 6. 순서

**②③은 병렬로 진행하세요.**

- [ ] **① 대회 마감일 확인** (PM)
- [ ] **② 원스토어 개발자센터 가입** — 무료, 본인인증
- [ ] **③ 서버를 상시 가동 환경으로 이전** — Oracle Cloud Always Free (인프라)
- [ ] ④ 최종 서버 주소 확정 → `API_BASE_URL` 시크릿 갱신
- [ ] ⑤ 릴리스 키스토어 생성 + CI 시크릿 등록 (인프라)
- [ ] ⑥ `build.gradle.kts` 릴리스 서명 설정 + `flutter build apk --release` 잡 (인프라)
- [ ] ⑦ 개인정보처리방침 작성(PM) → 서버에 공개 URL 로 게시(인프라)
- [ ] ⑧ 스토어 등록 자료 — 아이콘·그래픽·스크린샷·설명 (PM/UI)
- [ ] ⑨ 원스토어에 상품 등록 + 릴리스 APK 업로드 → 심사(1~2시간)
- [ ] ⑩ 테스트 계정 `openapi@…` 생성 및 동작 확인
- [ ] ⑪ 스토어 링크를 심사자료에 제출

**핵심 경로는 ③④⑤⑥입니다** — 서버 주소가 확정돼야 스토어에 올릴 빌드를 만들 수 있습니다.
