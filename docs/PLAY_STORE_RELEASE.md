## 0. 왜 출시가 "선택"이 아니라 "제출 요건"인가

대회 1차 심사자료 안내가 서비스 유형별로 제출물을 이렇게 규정합니다.

> **앱**: 구글 스토어, 애플 스토어, 원스토어 등 **최소 1개 스토어에 등록 완료된 링크 입력**

**디버그 APK 를 링크로 나눠주는 것으로는 요건을 못 채웁니다.** 실제로 스토어에 올라가 있어야 합니다.

**iOS 는 범위에서 뺐습니다**(2026-09-08 결정). "최소 1개" 조건이라 Google Play 하나로 충족되고, Apple Developer Program 은 **$99/년**이 매년 나가는 반면 Play 는 **$25 일회성**입니다.

---

## 1. ⏱ 임계 경로 — 여기서 일정이 결정됩니다

**계정 종류에 따라 최소 소요가 2주 넘게 갈립니다.** 이 문서에서 가장 중요한 표입니다.

| | 개인(Personal) | 조직(Organization) |
|---|---|---|
| 등록비 | **$25 일회성** (연간 아님) | $25 일회성 |
| 신원 확인 | 정부 발급 신분증 + 본인 명의 카드, 2단계 인증 | 위 + **D-U-N-S 번호** |
| **비공개 테스트 의무** | **테스터 12명 × 14일 연속** | **면제** |
| 준비 기간 | **최소 2주 이상** | D-U-N-S 발급에 **수 주** |

> 🔴 **개인 계정의 "12명 × 14일" 이 가장 큰 제약입니다.**
> 2023-11-13 이후 만든 개인 계정은, 테스터 **12명 이상**이 **14일 연속** 비공개 테스트에
> 참여한 뒤에야 프로덕션 액세스를 신청할 수 있습니다. 신청 후 검토 시간이 또 붙습니다.
>
> **우리 팀은 5명입니다. 최소 7명을 외부에서 더 모아야 하고, 그들이 14일 동안 테스터로
> 남아 있어야 합니다.** 중간에 빠지면 카운트가 깨집니다.

> ⚠️ 조직 계정은 12/14 를 면제받지만 **D-U-N-S 번호**가 필요하고 발급에 수 주 걸립니다.
> 학교·단체 명의를 쓸 수 있는지가 관건인데, 이미 번호가 있는 조직이 아니면 개인보다 느립니다.

### 🚨 먼저 확인해야 할 것: 대회 마감일

저장소 어디에도 마감일이 없습니다. **개인 계정 기준으로 최소 2주가 필요하므로, 남은 기간이
3주 미만이면 지금 당장 계정 등록과 테스터 모집을 시작해야 합니다.**

## 2. 기술적으로 막혀 있는 것

### 🔴 2-1. 릴리스 서명 — 지금은 디버그 키로 서명됩니다

[`app/android/app/build.gradle.kts`](../app/android/app/build.gradle.kts) 현재 상태:

```kotlin
buildTypes {
    release {
        // TODO: Add your own signing config for the release build.
        signingConfig = signingConfigs.getByName("debug")   // ← 스토어가 거부합니다
    }
}
```

디버그 키로 서명된 빌드는 **Play Console 이 업로드 자체를 거부**합니다. 업로드 키스토어를 만들어야 합니다.

> ⛔ **키스토어(`.jks`)와 비밀번호는 저장소에 커밋하지 않습니다.** `.env`·서비스 계정 키와 같은
> 취급입니다. CI 에서는 base64 로 인코딩해 **저장소 시크릿**에 넣고, 빌드 시 복원합니다.
>
> ⚠️ **업로드 키를 잃어버리면 앱을 영영 업데이트할 수 없습니다.** Play 앱 서명(Play App Signing)을
> 켜면 구글이 서명 키를 보관해 주므로 **반드시 켜세요** — 업로드 키만 잃어도 재발급이 됩니다.

### 🔴 2-2. `.aab` 가 필요합니다 — APK 가 아닙니다

Play 는 신규 앱에 **Android App Bundle** 을 요구합니다. 지금 CI 는 `flutter build apk --debug` 만 합니다.

```
flutter build appbundle --release   # → build/app/outputs/bundle/release/app-release.aab
```

디버그 APK 빌드는 **그대로 둡니다.** 팀 내부 확인용으로 계속 쓰이고, 스토어용 `.aab` 는 별도 잡으로 붙입니다.

### 🟠 2-3. 확인이 필요한 것

| | 현재 | 확인할 것 |
|---|---|---|
| `targetSdk` | `flutter.targetSdkVersion` (Flutter 기본값) | Play 의 최신 타깃 API 요구 수준을 만족하는지 |
| `versionCode` | `1` (`version: 0.1.0+1`) | 업로드마다 올라가야 합니다. 같은 값으로 두 번 못 올립니다 |
| `applicationId` | `com.fogapp.fogapp` | 한 번 정하면 **영영 못 바꿉니다.** 이대로 갈지 확정 |

## 3. 스토어 등록에 필요한 자료 (코드 밖의 일)

| | 비고 |
|---|---|
| **개인정보처리방침 URL** | **필수.** 위치·카메라 권한을 쓰는 앱은 없으면 등록이 안 됩니다. 공개 URL 이어야 합니다 |
| **데이터 세이프티 양식** | 수집 항목을 선언합니다 — 위치, 사진, 이메일. 실제 동작과 다르면 정책 위반입니다 |
| **콘텐츠 등급 설문** | 사용자 생성 콘텐츠(발자취 글귀)가 있다는 점을 반영해야 합니다 |
| 앱 아이콘 512×512, 그래픽 이미지 1024×500 | |
| 스크린샷 최소 2장 | |
| 짧은 설명(80자) · 자세한 설명(4000자) | |

> 💡 **개인정보처리방침 URL 은 인프라가 붙일 수 있습니다.** 이미 공개 HTTPS 서버가 있으니
> 정적 페이지 하나를 서빙하면 됩니다. **문구는 PM 이 써야 합니다** — 실제 수집 항목과 어긋나면
> 정책 위반입니다.

## 4. 🔑 대회 제출용 테스트 계정

심사자료 안내가 **계정 형식을 지정**했습니다. 임의로 만들면 안 됩니다.

| 형식 | ID | PW |
|---|---|---|
| 일반계정 | `openapi` | `2026openapi!` |
| **이메일 계정** | `openapi@메일도메인` | `2026openapi!` |

**우리 앱은 이메일 로그인이므로 이메일 형식을 씁니다.** Firebase Auth 에 이 계정을 만들어 제출합니다.

> ⚠️ 이 계정으로 심사위원이 **실제로 앱을 돌려봅니다.** 만들어만 두면 안 되고, 로그인 → 지도 →
> 스팟 인증까지 되는지 미리 확인해야 합니다.
>
> ⚠️ 발자취 작성 횟수(`users.footprint_quota`)가 기본 3 이라, 심사 중 소진되면 기능을 못 봅니다.
> 제출 전에 이 계정의 잔여 횟수를 확인하세요.

## 5. 🔴 서버가 24시간 떠 있어야 합니다

**이게 이번 범위 변경에서 가장 큰 영향입니다.**

지금 서버는 **인프라 담당자의 PC** 에서 Tailscale Funnel 로 나갑니다. 우리가 옆에서 시연하는 형식이면 괜찮았지만, **스토어에 올라간 앱을 심사위원이 각자 시간에 설치해 써 본다면** PC 가 꺼져 있는 순간 로그인부터 실패합니다.

**상시 가동 서버로 옮겨야 합니다.** 조사해 둔 선택지 중 **Oracle Cloud Always Free(0원)** 가 우리 스택에 맞습니다 — PostGIS 를 직접 호스팅하고, 200GB 블록 스토리지에 인증 사진 볼륨을 붙일 수 있습니다.

> ⚠️ **서버 주소가 바뀌면 앱을 다시 빌드해 스토어에 올려야 합니다.** `API_BASE_URL` 이 빌드
> 타임에 구워지기 때문입니다. **스토어에 올리기 전에 최종 주소를 확정하세요.** 순서를 반대로
> 하면 심사 기간에 업데이트를 한 번 더 태워야 합니다.

## 6. 순서

**앞의 두 개는 병렬로 진행하세요. 계정 승인과 서버 이전이 임계 경로입니다.**

- [ ] **① 대회 마감일 확인** — 남은 기간에 따라 계정 종류가 갈립니다 (PM)
- [ ] **② Play Console 계정 등록** ($25, 개인/조직 결정, 신원 확인)
- [ ] **③ 서버를 상시 가동 환경으로 이전** — Oracle Cloud Always Free (인프라)
- [ ] ④ 최종 서버 주소 확정 → `API_BASE_URL` 시크릿 갱신
- [ ] ⑤ 업로드 키스토어 생성 + `key.properties` + CI 시크릿 등록 (인프라)
- [ ] ⑥ `build.gradle.kts` 릴리스 서명 설정 (인프라)
- [ ] ⑦ CI 에 `.aab` 빌드 잡 추가 (인프라)
- [ ] ⑧ 개인정보처리방침 작성(PM) → 서버에 공개 URL 로 게시(인프라)
- [ ] ⑨ 스토어 등록 정보 — 아이콘·스크린샷·설명·데이터 세이프티·콘텐츠 등급 (PM/UI)
- [ ] ⑩ **비공개 테스트 12명 × 14일** (개인 계정인 경우) — 전원
